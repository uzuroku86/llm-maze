# MVP

## 目的

このMVPの目的は、

**「思考構造を3D空間として表現し、その中を実際に歩く体験が面白いか」**

を最小構成で確認することです。

この段階では、完成されたゲームを作ることや、LLMとの本格的な対話機能を実装することは目的としません。

---

## 検証したい仮説

以下の仮説を検証します。

> 論点や仮説を、文章やグラフではなく「部屋」「道」「分岐」として3D空間に変換すると、思考を探索している感覚を得られるのではないか。

特に以下を確認します。

- 思考の分岐を「道の分岐」として見ると直感的に理解できるか
- 思考の先へ実際に歩いていく行為に面白さがあるか
- 次の論点が空間の奥に存在することで「続きを探索したい」と感じるか
- 通常のチャットUIとは異なる体験になるか

---

# MVPの範囲

## 1. Thought Graph

固定されたJSONデータから思考構造を読み込みます。

最初のMVPではLLMは使用しません。

例:

```json
{
  "id": "root",
  "label": "今の仕事を続けるべきか？",
  "branches": [
    {
      "id": "growth",
      "label": "今の仕事で成長できているか？"
    },
    {
      "id": "interest",
      "label": "仕事そのものに興味を持てているか？"
    },
    {
      "id": "fatigue",
      "label": "単純に疲れているだけではないか？"
    }
  ]
}
```

---

## 2. 3D空間への変換

Thought Graphを3D空間として表現します。

最低限、以下を実装します。

- 現在の論点を表す場所
- そこから伸びる複数の道
- 道の先にある次の論点
- Thought Graphの分岐と3D空間の分岐を対応させる

最初のMVPでは、複雑な迷路生成は行いません。

例えば3つの仮説が存在する場合、

```text
                道A
                 │
                 │
                 ●

START ────────── ● ────────── 道B

                 │
                 │
                 ●
                道C
```

のような単純な構造で構いません。

---

## 3. プレイヤー操作

プレイヤーが3D空間を自由に移動できるようにします。

最低限必要な操作:

- WASDによる移動
- マウスによる視点移動

ゲームとして高度な操作性は必要ありません。

「思考空間の中を歩ける」ことを最優先します。

---

## 4. 思考内容の表示

各道または道の先に、その思考の内容を表示します。

例:

```text
今の仕事を続けるべきか？
```

という地点から、

```text
今の仕事で成長できているか？
```

```text
仕事そのものに興味を持てているか？
```

```text
単純に疲れているだけではないか？
```

という3本の道が伸びます。

プレイヤーが遠くから見ても、

「この道を進むと何について考えることになるのか」

がある程度分かるようにします。

---

# 最初のVertical Slice

最初に完成させるVertical Sliceは以下です。

```text
固定JSON
   ↓
Thought Graph読み込み
   ↓
3D空間生成
   ↓
3本の道を表示
   ↓
それぞれの道に論点を表示
   ↓
プレイヤーがWASDで歩く
```

ここまでを最初の完成地点とします。

以下はこのMVPでは実装しません。

- リアルタイムのThought Graph生成
- LLMとの会話
- プロンプト生成
- 推論内容の自動解析

- 戦闘
- HP
- スコア
- レベル
- アイテム
- クエスト
- キャラクター育成
- NPC
- マルチプレイ

## アプリケーション機能

- ログイン
- ユーザー管理
- データベース
- セーブ
- ロード
- クラウド同期

## 高度な表現

- 本格的な迷路生成
- 高度なライティング
- 高品質な3Dモデル
- キャラクターアニメーション

これらは基本体験が面白いと確認できてから追加します。

# データ構造

最初は非常に単純な構造とします。

```ts
type ThoughtNode = {
  id: string;
  label: string;
  branches?: ThoughtNode[];
};
```

将来的には以下のような属性を追加する可能性があります。

```ts
type ThoughtNode = {
  id: string;
  label: string;

  type:
    | "issue"
    | "hypothesis"
    | "question"
    | "conclusion";

  uncertainty?: number;
  evidenceStrength?: number;

  branches?: ThoughtNode[];
};
```

ただし、MVPでは必要になるまで追加しません。

---

# 完成条件

以下をすべて満たしたら、このMVPは完成とします。

- ブラウザ上で3D空間が表示される
- プレイヤーがWASDで移動できる
- マウスで周囲を見渡せる
- 固定JSONからThought Graphを読み込める
- 1つの論点から複数の道が生成される
- 各道が別の思考を表している
- 道の先または道の近くに思考内容が表示される
- 実際にその道を歩いて次の思考へ向かえる

---

# MVP完成後に確認すること

実装が完了したら、機能数ではなく体験を評価します。

以下について実際に触って判断します。

1. 思考の分岐を歩くこと自体に面白さを感じるか
2. 次の道を選ぶ感覚が「思考を選ぶ感覚」と結びつくか
3. 文章を読むだけの場合より思考構造を理解しやすいか
4. 空間の先を見たときに探索したくなるか
5. LLMとのリアルタイム対話を追加したくなる程度の可能性を感じるか

この段階で面白さを感じなければ、機能を追加する前に空間表現そのものを再検討します。

---

# 次の段階

このMVPが成立した場合、次に以下を検討します。

1. 道の先まで歩くと新しいThought Nodeを選択できる
2. 選択したNodeからさらに新しい道を生成する
3. Thought Graphを動的に拡張する
4. LLM APIを接続する
5. プレイヤーの入力から新しい思考分岐を生成する

最終的には、

```text
プレイヤーの相談
      ↓
LLM
      ↓
Thought Graph
      ↓
3D空間
      ↓
プレイヤーが探索
      ↓
追加の問い
      ↓
LLM
      ↓
新しい空間が生成される
```

というループを実現することを目指します。

ただし、MVPではここまで実装しません。
